# Tomato Monster (macOS) · PRD · v3-notion-goals-sync

> 文件位置:`iterations/v3-notion-goals-sync/PRD.md`
> 配合项目根的 [BRIEF.md](../../BRIEF.md) 阅读。这份 PRD 描述月度目标同步到 Notion 的迭代。

## 1. 项目背景

v2 已完成本地月度目标:目标跨月保留,进度按自然月重新计算,每日可一键加入任务。v3 补齐 BRIEF 中「记录沉淀到用户自己的 Notion」这一环,把当前月目标作为月度快照写入既有 Notion 体系。

## 2. 本次目标

- 用户点击一次,即可把当前月全部 App 目标同步到 Notion。
- 每个目标每月生成一条独立快照,并关联到「时间框架」当月页面。
- 重复同步只更新原记录,不产生重复数据。
- Notion 故障不影响本地目标、番茄结算或休息流程。

## 3. 用户与关键场景

### 场景 1:首次完成配置

- **用户**:已在 Notion 建好目标库并使用现有任务导出的作者。
- **旅程**:在设置中填写月度目标 DB ID → 测试连接 → App 校验数据库属性、relation 指向与读取权限。
- **结果**:看到可自动验证的连接及 schema 已通过,并确认 relation 数量限制的人工前置条件后,可以开始同步。

### 场景 2:同步本月目标

- **用户**:月初已在 App 中设置本月目标的作者。
- **旅程**:打开「月度番茄目标」卡 → 点击「同步本月到 Notion」。
- **结果**:当前月每个目标形成一条 Notion 记录,并关联到唯一的月份页面。

### 场景 3:回写最新进度

- **用户**:本月已完成若干番茄,希望更新 Notion 复盘数据的作者。
- **旅程**:再次点击同步 → App 根据本地最新数据更新已有月度记录。
- **结果**:名称、分类、计划量和完成量与 App 一致,没有重复记录。

### 场景 4:配置或月份页面异常

- **用户**:Notion 权限、属性或时间框架页面存在问题的作者。
- **旅程**:点击同步 → App 在写入前发现读取权限、schema 错误、无当月页面或存在多个当月页面。
- **结果**:同步停止并显示可行动的原因,本地数据完全不受影响。

### 场景 5:目标改名或删除

- **用户**:在 App 中调整目标的作者。
- **旅程**:改名后再次同步,或删除本地目标。
- **结果**:改名通过稳定 ID 更新原记录;删除不会清理 Notion 中已经形成的月度历史。

## 4. 界面结构

| 界面 | v3 变化 |
|---|---|
| 主面板 | 无变化 |
| 「🎯 月度番茄目标」卡 | 增加当前月份说明、「同步本月到 Notion」按钮及同步结果 |
| 「📤 Notion 导出」卡 | 增加月度目标 DB ID;连接测试覆盖目标库 schema 和 relation |
| 既有每日任务导出 | 行为与字段完全不变 |

## 5. 信息架构

### 月度目标卡 · 同步区

- **当前月份**:明确本次只同步哪个自然月。
- **同步动作**:一个「同步本月到 Notion」按钮。
- **过程状态**:未配置 / 校验中 / 同步中。
- **结果摘要**:新增 N / 更新 N / 失败 N。
- **错误反馈**:权限、属性类型、月份页面、单条写入错误及重试提示。
- **最近摘要**:App 重开后显示最近一次月度同步的月份、时间和三个计数;逐项目错误只在当次窗口内展示。

### Notion 配置卡

- 保留:Token / 任务 DB ID / 日页面 DB ID。
- 新增:月度目标 DB ID。
- 测试连接时校验:
  - 目标库 6 个属性的名称与类型,以及「分类」的四个固定选项。
  - 「所属月」指向时间框架,且对应的双向 relation 属性存在。
  - 时间框架具备 `类型:select`(含「月」)与 `日期:date`。
  - Integration 对两个数据库均有读取权限。
- 两套配置独立反馈:月度目标 DB ID 缺失或错误只禁用月度同步,不阻断既有每日任务导出。
- Notion API 不暴露 relation 的单页 / 多页 UI 限制;「所属月」限单页、时间框架反向 relation 允许多页由用户在 Notion 中预先确认,App 每次只写入一个「所属月」。

### Notion 月度目标记录

| 属性 | Notion 类型 | 同步内容 |
|---|---|---|
| 名称 | title | `YYYY-MM · App 目标名称` |
| 分类 | select | App 目标自身分类;选项严格为工作 / 学习 / 生活 / 兴趣爱好 |
| 本月总量 | number | App 目标的月度计划量 |
| 已完成 | number | 当前自然月关联任务的实际番茄总和 |
| 所属月 | relation | 时间框架中唯一的当月页面 |
| 本地目标 ID | rich_text | App 中跨月固定的目标 ID |

## 6. 交互规则

- **单向同步**:App 是唯一事实来源;Notion 修改不会反向覆盖 App。
- **手动触发**:只有点击按钮才同步,不做后台或自动同步。
- **当前月限定**:只处理当前自然月,不提供历史月份选择。
- **配置发现**:不新增时间框架 DB ID;App 从「所属月」relation schema 取得时间框架数据源,无法取得时停止。
- **月份定位**:时间框架中 `类型 = 月`,且 `日期`区间包含今天。
- **月份异常**:匹配结果不是唯一一条时停止,不自动创建或猜测页面。
- **稳定防重**:以 `所属月 + 本地目标 ID` 匹配记录,标题不作为唯一键。
- **重复键冲突**:远端同一复合键已有多条记录时,该目标失败并提示清理,不猜测更新其中一条。
- **重复同步**:已有记录更新名称、分类、本月总量和已完成;没有记录才创建。
- **分类口径**:直接使用 App 目标分类,不从任务标题或历史记录猜测。
- **空目标保护**:当前月没有本地目标时显示提示,不发起任何 Notion 写请求。
- **并发保护**:一次同步执行期间禁用同步按钮,同一窗口不得并发触发第二次。
- **快照一致性**:点击后先等待已触发的本地目标保存,再取得一次新的 Rust Snapshot;日期、目标字段和完成量在本次请求全程冻结,后续 `state-update` 不改变正在执行的 payload。
- **编辑保护**:同步状态和每秒快照只更新独立状态区;已有目标行复用 DOM,不得打断当前输入焦点或未提交草稿。
- **删除保护**:本地删除目标不删除、不归档 Notion 历史记录。
- **失败隔离**:读取权限、schema 或月份预检失败时零写入;写权限等逐条写入错误允许部分成功,并提供失败明细。修复后重复同步即可补齐。
- **摘要记账**:最近摘要采用 best-effort 记账;本地落盘失败不改变已经发生的远端 `created / updated / failed / ok`,预检失败也不覆盖上一次成功进入写入阶段的摘要。

## 7. 目标衡量

**上线后 30 天:**

- 至少完成 4 次本月目标同步。
- 每次同步后 App 与 Notion 的目标字段一致。
- 同一目标同一月份的重复记录数为 `0`。
- 人工修正 relation 或同步数值的次数为 `0`。
- Notion 故障导致本地保存或番茄结算失败的次数为 `0`。

以上 30 天指标由作者根据 App 最近一次摘要和 Notion 数据手工验收,本版本不增加遥测。

**同步漏斗:**

配置 DB ID → schema 校验通过 → 点击同步 → 唯一当月页面命中 → 全部目标创建或更新 → Notion 数据核对一致。

## 8. 范围

**这一版会做:**

- 当前月目标手动单向同步
- schema 与权限预检
- 当月页面定位
- 按稳定 ID 幂等创建或更新
- 进度回写
- 部分失败反馈与安全重试
- Notion 配置及最近一次同步摘要(月份、时间、计数;Rust 按计数字段白名单持久化,不含 Token、DB ID、标题、逐项目错误或请求内容)

**这一版不做:**

- 自动或后台同步
- Notion → App 导入或双向同步
- 历史月份选择与补同步
- 自动创建时间框架页面
- 自动删除或归档远端记录
- 改造既有每日任务导出
- 月度分析看板、目标排序或新增激励功能

## 9. 风险与待解决问题

- Integration 必须同时连接「月度番茄目标」和「时间框架」数据库。
- 自动预检只能证明读取权限;创建或更新权限错误会在逐条写入时报告。
- Relation 的单页 / 多页 UI 限制无法通过 Notion API 自动验证,属于同步前的人工前置条件。
- Token 与数据库 ID 只保存在本机,不进入备份、日志或项目文档。
- 用户后续修改 Notion 属性名称、类型或 relation 时,schema 预检必须阻止错误写入。
- Notion 不提供批量事务;逐条写入可能部分成功,必须依靠幂等重试收口。
- 既有每日任务导出是回归保护范围,v3 不得改变其字段或行为。

**用户补充的项目独有风险或待解决问题:**

- 无。
