# Phase 04 — 月度目标同步 UI 与真实闭环

**Status**: `not started`
**目标**: 用户可在月度目标卡一键同步当前月，并在真实 Notion 中安全完成首次新增与后续更新
**前置**: Phase 03 已验收并提交；App 中已填写月度目标 DB ID，所用 Integration 可访问目标库和时间框架

## 验收判据

- 「月度番茄目标」卡显示 Rust 快照对应的当前月份、「同步本月到 Notion」按钮、过程状态、结果摘要和错误明细
- 未配置时按钮明确提示去配置；无本地目标时显示空提示且没有网络写请求
- 同步期间按钮禁用并防止双击；已有目标编辑输入的焦点和草稿不因同步状态更新而丢失
- 第一次真实同步为当前每个 App 目标创建一条记录，六字段及唯一「所属月」relation 与 App 一致
- 不修改本地数据再次同步只更新已有记录，不产生相同 `所属月 + 本地目标 ID` 的重复页
- 改名、改分类、改本月总量或产生新完成量后再次同步，仍更新同一 Notion 页面并反映最新字段
- 读取/schema/月页错误在写入前停止；单条写权限或 payload 错误进入失败明细，本地目标保存、计时和休息流程不受影响
- App 重开后能显示最近一次不含敏感信息的月份、时间和新增/更新/失败摘要

## Tasks

- [ ] 在月度目标卡增加当前月份、同步按钮、状态区和最近一次摘要，位置与文案遵循 PRD
- [ ] 使用现有 DESIGN token 完成 normal / hover / disabled / loading / success / partial / error 状态，不引入新视觉体系
- [ ] 将 Phase 02 预检和 Phase 03 同步核心接入按钮，保证一次操作使用冻结的 Rust 快照与 Notion 配置
- [ ] 防止并发触发，并在状态刷新时复用既有目标表单 DOM，保护输入焦点和未提交草稿
- [ ] 在真实 Notion 执行首次新增、无变更重同步、字段变更重同步三轮验收，逐项核对六字段、relation 和零重复
- [ ] 验证失败反馈不影响本地目标增删改、番茄计时或休息状态，并记录不含 Token / DB ID / 用户任务标题的 evidence
- [ ] 运行 JS 测试、Rust 测试、语法与样式检查，整理用户 5 分钟内可完成的验收步骤

## Notes

- 这是本迭代首次获准向真实 Notion 写入的 Phase。只同步用户当前已有目标，不创建额外测试数据库，也不自动清理远端页面。
- 开始真实验收前必须再次说明点击按钮会新增或更新用户现有 Notion 页面；由用户亲自触发，evidence 只记录计数与核对结论。
- 创建或更新权限无法在只读阶段提前证明；若首次写入返回权限错误，应保留本地数据并给出重新连接 Integration 后重试的指引。
- 结果摘要必须区分新增、更新和失败；不得沿用每日导出只显示“已导入 0”的模糊反馈。
