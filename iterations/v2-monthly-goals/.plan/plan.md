# 修掉跨天残留、把面板加宽，并让每天固定要做的事变成"勾一下"

> 文件位置：`iterations/v2-monthly-goals/.plan/plan.md`
> 配套 skill：first-flight-phases
> 本 plan 文档是**稳定航图**，状态跟踪在各 phase 文档（同目录的 `phases/NN-*.md`）里。

## 背景

v1 上线并日常使用两个月后暴露三个问题：跨天任务不自动归档、面板 300px 太窄、每天重复输入同样的任务名。本迭代解决这三件事。设计已通过 baoyu-design 画布定稿并经用户逐项拍板（宽度 360 / 两行任务行 / chips 内嵌 / 本月总量语义 / 原生数字框 / 不自动重置 / 已投入锁定），设计稿见 `designs/panel-v2-monthly-goals/`。

## 范围

**做：**

- 跨天日切修复（tick 线程补调归档）
- 面板 300 → 360px、高度 480 → 560px、任务行两行排
- 月度目标数据模型 + commands（Rust）
- 月度目标 chips（主面板）+ 今日番茄数可改（数字框）
- 「🎯 月度番茄目标」管理卡（统计与设置窗口）

**不做：**

- Notion 联动（v3，落点已定为独立目标库 + relation）
- 月度目标的历史统计视图、目标拖拽排序
- 任何触及产品红线的改动（休息跳过出口、分类常量、奖励导向）

## 关键决策

- **2026-08-24**：**先修 bug 再加功能**（01 在最前）——跨天残留是每天都会遇到的数据正确性问题，独立且可立即验证，不和 UI 改动混在一起，方便单独回归。
- **2026-08-24**：**加宽（02）先于月度目标（03-05）**——月度目标的 chips 行和两行任务行都建立在 360px 布局上，宽度不先定死，UI 要返工。
- **2026-08-24**：**Rust 先行（03）再做 UI（04-05）**——沿用 v1 的做法与 AGENTS 规则 6，状态与持久化立住之前不写前端。
- **2026-08-24**：设置里的数字语义定为**本月总量**而非每日默认（用户拍板）——功能叫"月度目标"，chip 上显示 `12/30` 月进度才名副其实；今日番茄数每天在面板上敲。
- **2026-08-24**：番茄数控件**沿用现有 `type=number` 数字框**（用户拍板）——项目里"添加"那行已经是这个控件，自带上下箭头，既能敲也能点，不引入自定义 −/+ 按钮这套新词汇。
- **2026-08-24**：月度目标**永不自动重置**（用户拍板）——跨月只有进度归零重新计，条目原样保留，增删改全部手动。
- **2026-08-24**：**Notion 联动推迟到 v3**（用户拍板）——落点方案已定（独立「月度番茄目标」库 + relation 挂到时间框架月度页），但需要用户先在 Notion 建库并提供库 ID；v2 先把本地版用顺手。
