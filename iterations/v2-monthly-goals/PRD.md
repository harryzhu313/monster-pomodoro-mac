## 1. 项目背景

v1 上线后作者已日常使用两个月,暴露出三个问题:

1. **跨天数据残留**:第二天早上打开面板,昨天的任务还在"今日任务"里;点一次"统计与设置"再回来才消失。
2. **面板过窄**(300px):任务名一长就被挤压换行,添加框的 placeholder 也被截断。
3. **重复输入成本高**:"内参阅读""内驱式学习"这类每天都做的事,每天都要重新打字、重选分类、重设番茄数。

## 2. 本次目标

- 跨天自动归档,不需要任何手动操作
- 面板加宽到 360px,长任务名不再难看
- 新增「月度目标」:一次设定,每天勾选即加入今日任务

**不做**(留给 v3):

- Notion 联动(月度目标导入到「时间框架」月度页)——落点方案已定为**独立目标库 + relation**,见 §7
- 月度目标进度回写 Notion

## 3. 用户与关键场景

### 场景 1:第二天早上打开面板

作者早上点开托盘面板,"今日任务"是干净的——昨天的任务已自动归档进历史,不需要点任何地方。

### 场景 2:开始今天的固定项目

作者点开面板,「8 月目标」那行有三个 chip(内参阅读 / 内驱式学习 / 网站建设完成)。点一下"内参阅读",它按预设的「学习」分类进入今日任务,今天想做几个就在任务行的数字框里敲。全程不打字。

### 场景 3:月初设定这个月要做什么

作者在「统计与设置」的「月度番茄目标」卡里写下本月三个目标,每个填分类和本月总量(如内参阅读 30 个)。写完就不用管了——不会自动重置,想改随时回来改。

### 场景 4:临时任务照旧

不属于月度目标的一次性任务(如"回访客户邮件"),仍然用原来的添加框手动加,行为不变。

## 5. 信息架构

### 主面板 · 今日任务卡(自上而下)

1. 卡头:「今日任务」+ "N 个完成"徽章
2. **月度目标行**(新增):
   - 小标题「{M} 月目标 · 勾选加入今天」+ 右侧「管理 ›」(跳统计与设置)
   - chips:每个目标一个胶囊,显示 `目标名 已完成/本月总量`;勾选态填番茄红
   - chips 下方一条细进度条:所有目标合计的本月进度
3. 添加框(原样)
4. 任务列表:**两行排**
   - 第一行:复选框 + 任务名 + 分类徽章 + 删除
   - 第二行:今日番茄数(`type=number` 数字框,自带上下箭头)+「已做 N」+「设为当前」

### 统计与设置 · 🎯 月度番茄目标卡

- 标题 + 副标题(当前月份说明)
- 目标列表:每行 = 名称 + 分类下拉 + 本月总量数字框 + 删除
- 底部一行新增:名称输入 + 分类下拉 + 数量 + 添加

## 6. 交互规则

| 规则 | 说明 |
|---|---|
| 勾选加入 | chip 勾上 = 按目标的**名称与分类**创建今日任务;今日番茄数默认 1 |
| 今日番茄数可改 | 在任务行的数字框里改,**只影响今天那条任务**,不回写月度目标 |
| 下限保护 | 今日番茄数不能小于今天已投入的数量(已做 3 个就改不到 2) |
| 已投入锁定 | 当天已投入番茄的目标,chip 不可取消勾选(取消会丢已有记录) |
| 取消再勾选 | 今日番茄数回到默认 1,上次的临时改动不粘住 |
| 永不自动重置 | 月度目标条目跨月原样保留,只有本月进度按自然月重新计;增删改只由用户手动进行 |
| 本月进度 | chip 上的"已完成"= 本月所有由该目标产生的任务的 `used` 之和 |

## 7. 目标衡量

- 早上打开面板看到昨天任务的次数:**0**
- 「内参阅读」这类固定项目从打开面板到进入今日任务:**1 次点击**(原来约 3 次操作 + 打字)
- 任务名 16 个汉字以内时标题不换行(实测值,含分类徽章占位;超出则在标题自己那一行内优雅折行,不再被右侧按钮挤压)

## 8. 范围

**做:** 跨天日切修复、面板 360px + 两行任务行、月度目标(本地)全链路(数据 / 面板 chips / 设置管理卡)

**不做:** Notion 联动(v3)、月度目标的历史统计视图、目标排序拖拽
